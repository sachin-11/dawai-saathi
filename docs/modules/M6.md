# M6 — Emergency guard, PHI redaction aur scope guard

## Is module me kya banaya
AI service ko medical kaam se pehle safe banaya. Teen guard bane: (1) **Emergency guard**: "seene me dard", "jeena nahi hai" jaise messages par turant 112 / 108 (self-harm me Tele-MANAS 14416) ka reply, koi LLM call nahi. (2) **PHI redaction**: Presidio + spaCy + Indian recognisers (mobile, Aadhaar-like, PAN, ABHA, PIN, hospital id, naam) se logs, Langfuse traces aur classifier input me personal data hat jaata hai. (3) **Scope guard**: bot sirf dawai, prescription aur lab report par baat karta hai; cricket, coding, diet advice par fixed polite reply. Emergency keywords ek hi shared file me hain jo gateway aur AI service dono padhte hain. 152 synthetic messages ka emergency eval set aur CI gate bhi bana.

## Kyun zaroori tha
Health bot ke liye sabse bada risk hai ek asli emergency miss ho jaye. Doosra risk: user ka phone/Aadhaar/naam logs ya traces me chala jaye. Teesra: WhatsApp Business policy general-purpose AI chatbot ko restrict karti hai, aur product bhi sirf medicine-focused hai, to off-topic sawalon par model free-write nahi kar sakta.

## Kaise kaam karta hai
```
user text ─► gateway pre-check (keyword, AI down ho tab bhi chalta hai) ──match──► 112/108 reply (priority 1)
                  │ no match
                  ▼  AI service  /v1/process
   1. rules (shared keyword file, <1 ms, fuzzy, filler words) ──match──► emergency template, STOP
   2. redact (Presidio)        ← sirf redacted text aage jaata hai
   3. emergency classifier (CHEAP model, confidence >= 0.5)   ← fail ho/timeout ho to rules ka verdict
   4. intent classifier v2 (redacted text) ─► help | greeting | out_of_scope | coming soon
   5. reply = STATIC template (model ke shabd user tak nahi jaate)
gateway: response.emergency ─► top priority send + audit "emergency_detected" {category}
```
Image/audio par emergency guard nahi chalta: prescription ke text me "chest pain" likha ho to wo history hai, emergency nahi. Code me `UserText` type sirf user ke typed message se banta hai, image se nahi.

## Important technical decisions
- **Recall > precision.** Ek galat "112 call karo" sasta hai, ek miss hui emergency nahi. Isliye classifier ka threshold 0.5 (kam), negation/history handling nahi ("no chest pain" bhi flag hota hai) aur fuzzy matching (edit distance 1). Trade-off: near-miss messages flag hote hain; eval report me alag se dikhte hain.
- **Do stage.** Rules fast aur deterministic hain, LLM paraphrase pakadta hai ("maa ki saans ukhad rahi hai"). LLM pe poora bharosa nahi: wo down ya galat ho sakta hai. Classifier fail-safe hai: error/timeout par request block nahi hoti, rules decide karte hain.
- **Gap-tolerant matching.** "seene me *bahut* dard" phrase "seene me dard" se match nahi hota tha (isi test me pakda gaya). Ab phrase ke beech me 2 filler words allowed hain.
- **Shared keyword file** `packages/contracts/safety/emergency-keywords.json` (JSON schema ke saath); har app me ek copy (`make safety-data`), stale hone par test fail. Normalisation ke shared test vectors se TypeScript aur Python ek jaisa behave karte hain.
- **Presidio me sirf allow-list entities.** Generic recognisers (DATE_TIME, LOCATION) dose, date aur lab values ko redact kar dete, isliye nahi liye. spaCy ka PERSON sirf context word (Mr, Dr, naam) ke baad maana jaata hai, kyunki small model "Metformin" ko insaan ka naam bol deta hai.
- **Fail closed.** Presidio engine fail ho to regex layer phir bhi phone/Aadhaar/email/PIN hata deti hai.
- **Overdose question** ("paracetamol ka overdose kitne mg par hota hai") safety-relevant maana: sirf emergency guidance, dose answer kabhi nahi.
- **Image size**: Presidio + spaCy se image 412 MB se 841 MB hui (spaCy model 12 MB build time par install, runtime par download nahi). Slim karne ke liye package tests aur phonenumbers ka geodata hataya.

## Production-ready points
- Rules stage har request par chalta hai aur bina LLM ke jawab deta hai; gateway pre-check AI service down hone par bhi kaam karta hai.
- Logs me sirf category, source aur count (matched words kabhi nahi); structlog processor `text|body|prompt|output` fields redact karta hai; Langfuse masks redacted.
- `REDACTION_ENABLED=false` production me refuse (boot fail).
- Tests: ai-service guard (har category x language, misspelling, repeated letters, long message me buried, classifier positive/negative/timeout), 80+ redaction tests (positive + medical-content negative), eval gate test; gateway: AiProcessor emergency (priority, audit category only, audit fail ho to bhi reply), router (pre-check par AI call nahi), shared redaction fixture, normalisation vectors; integration: AI emergency reply + audit row.
- Eval: `make eval-emergency` ya `uv run --project apps/ai-service python evals/run_emergency_eval.py --mode rules|fake|real`. Rules mode: keyword rows par recall 100% (86/86), clear negatives par 0 false positives; fake mode: sab positives par 100% (92/92). Real model ke saath manual run baaki (API key chahiye).

## Interview me kaise bolna hai
"Maine emergency detection do stage me banaya: pehle ek shared keyword file par fast rule engine, jo Hindi, Hinglish aur English me typing mistakes bhi pakadta hai, aur uske baad ek cheap LLM classifier jo un messages ko dekhta hai jo rules miss kar dein. Threshold deliberately low hai kyunki hamare liye recall precision se zyada important hai. Classifier fail ho jaye to bhi rules decide karte hain, aur gateway me ek alag pre-check hai jo AI service down hone par bhi chalta hai. Personal data ke liye Presidio plus Indian recognisers use kiye, par dose aur lab values ko redact nahi hone dete. Off-topic sawalon par model kuch likhta hi nahi, fixed template jaata hai. Sab kuch 152 messages ke eval set aur CI gate se guard hai."

## Possible interview questions
1. **False positive zyada aaye to?** Ye jaan-boojh kar accepted trade-off hai. Report me near-miss alag dikhte hain; hum keyword list ya classifier prompt tune karte hain, par recall 100% ke neeche nahi jaate. Zarurat ho to negation handling baad me, eval me recall check karke.
2. **Hindi/Hinglish kaise handle kiya?** Normalisation (Devanagari nukta/candrabindu fold, repeated letters squeeze), har category ke liye en/hi/hinglish phrases aur misspellings, fuzzy matching Roman words par, aur LLM classifier paraphrase ke liye.
3. **LLM pe emergency detection poora kyun nahi chhoda?** LLM down, slow ya galat ho sakta hai aur latency/cost lagti hai. Rules deterministic aur instant hain; LLM sirf extra safety net hai.
4. **Redaction ki limitations?** Honestly: bina context word ke naam (Hindi ya Roman me) pakadna mushkil hai, spaCy ka English model Indian naam kam jaanta hai, address sirf PIN/context words se. Isliye defence in depth: gateway regex, Presidio, aur prescription image ka text logs me jaata hi nahi.
5. **Image ke text par emergency guard kyun nahi?** Report me "chest pain" history hoti hai; usse emergency reply bhejna galat aur darawna hoga. Isliye type system (`UserText`) se enforce kiya.
6. **Scope guard WhatsApp policy se kaise jura hai?** Meta general-purpose AI chatbots ko restrict karta hai; humara assistant ek focused use-case hai, isliye off-topic par model nahi, static template jaata hai.
