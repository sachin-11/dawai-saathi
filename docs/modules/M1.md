# M1 — Local infra, database schema, readiness checks

## Is module me kya banaya
Local development ke liye poora infra: `docker-compose.yml` me Postgres 16, Redis 7 aur MinIO (S3 jaisa storage). Prisma se CLAUDE.md §6 ke saare 10 tables ka schema aur pehli migration (`init_schema`). Gateway me Prisma, Redis aur S3 ke clients, AI service me read-only SQLAlchemy access, aur dono apps me `GET /health/ready` jo Postgres/Redis/S3 check karta hai. Koi WhatsApp code, queue ya AI logic nahi hai.

## Kyun zaroori tha
M2 se aage har module ko DB, queue aur file storage chahiye. Agar har developer apni machine par alag tareeke se setup kare to "mere pe chal raha hai" wali problem aati hai. `make up` + `make migrate` se koi bhi ek hi minute me same environment bana sakta hai. Aur production (ECS) me load balancer ko batana padta hai ki instance traffic lene layak hai ya nahi: wahi kaam `/health/ready` karta hai.

## Kaise kaam karta hai
```
make up ──► docker compose
              ├─ postgres:16  (pg_trgm + pgcrypto, role dawai_ai_ro)  :5432
              ├─ redis:7      (AOF on)                                :6379
              ├─ minio        (S3 API :9000, console :9001)
              └─ minio-init   (one-shot: bucket dawai-media, private, expiry 30 din)
make migrate ──► prisma migrate deploy ──► tables + indexes + CHECK + GRANT SELECT (AI role)

                        GET /health/ready
Gateway (NestJS)  ──► ReadinessService ──► Postgres SELECT 1 ┐
                                        ├─► Redis PING        ├─ parallel, har ek ka 2 s timeout
                                        └─► S3 HeadBucket     ┘
                      sab ok → 200 {"status":"ok","checks":{...}}
                      koi fail → 503 {"status":"degraded","checks":{"redis":"fail",...}}

AI service (FastAPI) ──► read-only role (dawai_ai_ro) ──► sirf drugs / interactions / lab_tests
```
1. Compose me har service ka healthcheck hai, isliye `make up` tabhi return karta hai jab sab healthy ho.
2. `minio-init` ek baar chalke private bucket banata hai aur lifecycle rule lagata hai jisse purani images `MEDIA_RETENTION_DAYS` (default 30) baad apne aap delete ho jaati hain.
3. Gateway ke clients lazy hain: app tabhi connect karti hai jab pehli query aaye. Isse app (aur unit/e2e tests) bina Docker ke boot ho jaate hain, aur DB down ho to `/health/ready` batata hai, app crash nahi hoti.
4. `/health/live` sirf "process zinda hai" batata hai (restart decide karne ke liye). `/health/ready` dependencies check karta hai (traffic bhejna hai ya nahi, ye decide karne ke liye).

## Important technical decisions
- **Docker Compose**: ek command me poora stack, versions pinned. Trade-off: Docker Desktop chahiye.
- **PostgreSQL + `pg_trgm`**: dawai ke naam me spelling mistakes bahut hoti hain ("Dolo650" vs "Dolo 650"). Trigram index pe fuzzy search Postgres ke andar hi ho jaata hai, alag search engine nahi chahiye. Index Prisma express nahi kar sakta, isliye migration SQL me haath se likha (`drugs_brand_name_trgm_idx`, GIN).
- **Redis + AOF**: BullMQ ke jobs (M2) Redis me rehte hain; AOF on hai taaki restart par queued jobs na jaayein. Shared connection factory (`RedisService.createConnection`) isliye hai ki BullMQ ko apne connections chahiye, `maxRetriesPerRequest: null` ke saath.
- **MinIO local me, real S3 nahi**: free, offline, aur same S3 API. Sirf `S3_ENDPOINT` set karne par `forcePathStyle` ke saath MinIO se baat hoti hai; AWS par endpoint khali chhodte hain aur IAM role use hota hai. Code same rehta hai. Note: Docker Hub se `minio/minio` image hat gayi hai, isliye Chainguard ki `cgr.dev/chainguard/minio` use ki (usme `mc` bhi hai).
- **Phone number: hash + encrypted** (`users.wa_phone_hash` unique, `wa_phone_enc`): lookup hash se, message bhejne ke liye decrypt. Plain number DB me kabhi nahi.
- **Cascade delete = DPDP erasure**: user ki saari tables `ON DELETE CASCADE` hain, to `DELETE` command (M4) ek `DELETE FROM users` me sab saaf kar deti hai. Do jaanbujhkar exception: `audit_logs.user_id` pe FK nahi hai (taaki "user_deleted" ki anonymous entry bachi rahe), aur `medications.drug_id` `SET NULL` hai (drugs shared catalog hai).
- **`interactions` pe CHECK (`salt_a < salt_b`) + UNIQUE**: "A+B" aur "B+A" dono kabhi store nahi ho sakte, to lookup me galti ya duplicate nahi hoga.
- **AI service read-only, 3 layers me**: (1) code me sirf catalog ke models hain, (2) DB role `dawai_ai_ro` ko sirf 3 tables par SELECT hai, (3) har session `default_transaction_read_only=on` ke saath khulta hai. Ye CLAUDE.md §4 ka "AI service kabhi user data nahi likhegi" rule database level par enforce karta hai.
- **Prisma 6.19.3, 7/8 nahi**: npm par `latest` abhi 8.0 release candidate hai, aur 7.x me client setup badal gaya hai (driver adapters, naya generator) jo maine hamare CommonJS + Jest stack par try nahi kiya. Isliye stable 6.x pin kiya jo pakka chalta hai (Decisions Log me entry).

## Production-ready points
- **Security**: koi secret hard-coded nahi (sab `.env` se, safe local defaults); bucket private; DB errors me password/host kabhi log ya response me nahi aata (sirf error type); Prisma logs ko apne logger se route kiya taaki query ki details (PHI) console par na jaayein.
- **Reliability**: har health check ka 2 s timeout (`withTimeout`) aur `AbortSignal` se S3 request cancel; graceful shutdown me Prisma, Redis aur S3 connections band hote hain.
- **Testing**: gateway 33 unit + 6 e2e (bina Docker ke, unreachable infra par 503 verify), 11 integration (real Postgres/Redis/MinIO: user insert/read, cascade delete, audit row bachna, CHECK constraint, trigram search, HeadBucket); ai-service 29 unit + 7 integration (read-only role: `drugs` padh sakta hai, `users` par "permission denied", write par error). Integration tests sirf `*_test` naam ke DB par chalte hain, taaki dev data safe rahe.
- **Verified manually**: Redis band karne par gateway `/health/ready` 503 (`redis: "fail"`), wapas start karne par 200; Postgres band karne par dono apps 503; gateway ki production Docker image build karke `/health/ready` 200.
- **Honest gaps**: Langfuse (`make up-obs`) ka compose config valid hai par maine use start nahi kiya; CI ka naya `integration` job GitHub par pehli baar chalna baaki hai (uske steps local par simulate kiye hain).

## Interview me kaise bolna hai
"M1 me maine local infra aur data layer banaya. Docker Compose se Postgres, Redis aur MinIO ek command me chalte hain. Schema Prisma me hai: phone number hash plus encrypted store hota hai, user ki saari tables cascade delete hain taaki DPDP ke under erasure ek query me ho jaye, aur drug names ke liye trigram index hai fuzzy search ke liye. AI service ko maine database level par read-only rakha: alag DB role jo sirf catalog tables padh sakta hai, aur har session read-only transaction me. Dono services me `/health/ready` hai jo DB, Redis aur S3 ko 2 second timeout ke saath check karta hai aur kuch bhi down ho to 503 deta hai. Integration tests real containers par chalte hain, aur CI me bhi."

## Possible interview questions
1. **Liveness aur readiness me kya fark hai?** Liveness: process zinda hai, fail ho to restart. Readiness: dependencies theek hain, fail ho to load balancer traffic roke, restart nahi. Dependency down hone par restart karna bekaar hai aur galat bhi.
2. **AI service ko DB read-only kyun rakha?** Ownership rule: user state gateway ka hai. Code review par bharosa nahi, isliye DB role aur session level par enforce kiya, to bug ya galat URL se bhi write nahi ho sakta.
3. **`audit_logs` pe foreign key kyun nahi?** User delete hone par bhi "user_deleted" ka anonymous record bachana hai (compliance). FK hota to cascade usse bhi hata deta.
4. **`pg_trgm` kyun, Elasticsearch kyun nahi?** Catalog chhota/medium hai aur Postgres me hi hai, to extra service, sync aur cost nahi. Misspelling ke liye trigram kaafi hai; semantic fallback ke liye baad me Pinecone (M8).
5. **Local me MinIO kyun?** Real S3 jaisa API bina cost aur internet ke. Code me sirf endpoint ka fark hai, isliye same client local aur AWS dono par chalta hai.
6. **Tests bina Docker ke kaise chalte hain?** Clients lazy hain aur e2e test unreachable address deta hai: app boot hoti hai aur readiness 503 deti hai. Docker wale tests alag (`test:integration`, pytest marker) hain.
