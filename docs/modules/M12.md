# M12 — Lab report explainer (F3)

## Is module me kya banaya
User lab report ki photo ya PDF (6 pages tak) bhejta hai. Bot test ka naam, value, unit aur lab ki **chhapi hui reference range** padhta hai, har value ko us range se compare karta hai, aur simple Hindi/English me batata hai kaunsi value range ke andar hai, kaunsi bahar, aur wo test kya naapta hai. Saath me 2–3 "doctor se pooch sakte hain" sawaal aur critical value par sabse upar `🚨 ... aaj hi doctor se sampark karein`. Diagnosis kabhi nahi. Nayi cheezein: 5 graph nodes (`vision_extract_lab → lab_normalize → lab_compare → lab_gate`, aur typed sawaal ke liye `lab_question`), `lab_tests` table (65 tests), `lab_results` table, `REPORTS` command, `[Sab tests dekho]` / `[Galti hai]` buttons, aur 36 synthetic reports ka eval jisme 5 hard gates hain.

## Kyun zaroori tha
Lab report me sirf numbers aur H/L flags hote hain, matlab nahi. Isse ya to panic hota hai ya neglect. Par yahan do bade risk hain: (1) LLM se "aapko diabetes hai" jaisa verdict bulwana, (2) value ya unit galat padhna (lakhs/cumm vs /cumm, mmol/L vs mg/dL) aur critical value miss kar dena. Isliye model sirf **padhta** hai, baaki sab deterministic code.

## Kaise kaam karta hai
```
photo/PDF ─► prepare_image (6 pages tak) ─► classify (lab_report) ─► vision_extract_lab (VISION_MODEL, lab_extract_v1, 1 strict retry)
          ─► lab_normalize ─► lab_compare ─► lab_gate ─► composer (template) ─► verifier ─► reply + [Sab tests dekho] [Galti hai]
text ("TSH 6.2 matlab kya?") ─► emergency_guard ─► classify ─► lab_question (model sirf test ka naam copy karta hai)
          ─► DB explanation + general range ─► composer ─► verifier
```
- **lab_normalize** (`app/tools/lab_normalize.py`): value parse (`1,25,000`, `<0.5`, `1.2 x 10^3`, `Positive`), unit ek spelling me (`gm/dL`, `lakhs/cu.mm`, `µIU/mL`), test ka naam → `lab_tests.code` (pehle exact alias, phir trigram similarity threshold 0.6 + margin 0.1 + section hint + unit compatibility; do tests barabar likely ho to guess nahi). Canonical unit me value sirf comparison, critical aur trend ke liye; reply me value **jaisi chhapi hai** wahi dikhti hai.
- **lab_compare** (`app/tools/lab_compare.py`): range priority — (1) lab ki printed range (confidence ≥ threshold), (2) printed H/L flag, (3) `lab_tests` ki fallback range age/sex ke hisaab se; age/sex na ho to general adult range aur reply me bata dete hain. Categories ("Deficient <20, Insufficient 20–29 …") ko hum normal/abnormal me nahi badalte, label jaisa chhapa hai waisa dikhate hain. Status: `normal | high | low | borderline | critical_high | critical_low | qualitative_abnormal | unknown`.
- **Critical** (`app/safety/critical_values.yaml`, canonical unit me): value strictly limit ke paar ho to `critical_*`, aur wo har cheez ko override karta hai — lab ka "N" flag, model ka "normal", ya low-confidence read bhi (us case me line kehti hai "saaf padh nahi paya, lab se pakka karein", par 🚨 line phir bhi aati hai).
- **Trends**: gateway pichhli reports ke sirf `test_code, canonical value, unit, date` bhejta hai (12 mahine). Reply max 3 badlav dikhata hai, **bina judgement** ("HbA1c: 7.8 % (Mar 2026) → 7.2 % (Nov 2026)"), sirf itna jodte hain ki value ab range ke andar/bahar hai.
- **Verifier** (`app/tools/lab_verify.py`): har number data me hona chahiye, har bullet ka test naam report ka hona chahiye, har out-of-range ya critical result mention (ya "+N aur") ho, critical line sabse pehle, disclaimer maujood, aur diagnosis/treatment blocklist (hi/en/Hinglish: "aapko diabetes hai", "dawai lijiye", "diet"…) me kuch na mile. Fail ⇒ same data ka plain version (explanations/trends/questions ke bina).
- **Gateway**: `documents` (kind `lab_report`) + `lab_results` ek transaction me; button ids me `{document_id}`; `REPORTS` last 5 reports (2 + More pagination), `[Galti hai]` ⇒ document `needs_review` aur trends se bahar.

## Important technical decisions
- **Lab ki printed range ko priority**: alag lab/machine/method ki range alag hoti hai, isliye same Hb 12.2 ek lab me normal aur doosre me low ho sakta hai. Fallback range tabhi jab printed range padhi na jaye. Trade-off: model ne range galat padhi to status galat; isliye range ka confidence gate aur eval me `Printed range extraction` metric.
- **Composer LLM nahi, template**: spec me "TEXT_MODEL composer" tha, par maine reply poora template se banaya (explanations DB se, baaki fixed sentences). Trade-off: kam natural phrasing, par "model ne kuch jod diya" ka risk zero aur verifier proof de sakta hai. Zarurat ho to M7 jaisa one-line-per-item LLM baad me jod sakte hain.
- **Hindi explanation tab tak nahi jab tak human review na ho** (`lab_tests.hi_reviewed`): Hindi reply me structure Hindi me, par per-test explanation sirf English me ya reviewed Hindi me. Generic Hindi line sirf DB me hai, reply me repeat nahi hoti.
- **Age/sex data minimisation**: report par chhapi age/sex sirf us document ki extraction me rehti hai, `users` table me copy nahi hoti (DPDP).
- **Critical list conservative aur unreviewed**: koi free authoritative source nahi; "needless 🚨" theek hai, "missed 🚨" nahi. `doctor_review_pending: true` — launch blocker.
- **Borderline** = range ke andar par limit ke 5% ke paas; narrow range (sodium 135–145) me poora hissa borderline na ho isliye margin range-width ke 10% tak capped (spec ka literal "5% of limit" sodium 139 ko borderline bana deta tha).
- **Fail closed**: lab catalog (DB) na mile to "abhi jaankari nahi dekh pa raha" — critical check chalaye bina reply nahi.

## Production-ready points
- Eval (`make eval-lab`, 36 synthetic reports, multi-page PDF, category ranges, mixed units, blur/rotation, fake names/ids): fake aur fake-noisy dono me hard gates 0 — critical recall 12/12, critical line first, diagnosis wording 0, page par na-mili value 0, PHI leakage 0. Noisy mode ne ek asli bug pakda: ek invented test ki low-confidence value "unclear" list me echo ho rahi thi; ab aisi value kabhi repeat nahi hoti.
- Tests: normalisation/compare (≈120 cases), verifier tampering, graph branches (emergency guard report text par nahi chalta), endpoint, real Postgres par seed script (idempotent) + Pg = in-memory parity + AI role read-only, gateway int-spec (webhook → `lab_results`, trends context, buttons, REPORTS, foreign id, cascade).
- `lab_results` par AI service ka koi grant nahi; audit me sirf action (`lab_reported_wrong`), koi content nahi.
- **Verified nahi hua**: real model par `lab_extract_v1` (sirf fake replay), real phone photos / real PDFs, Langfuse, WhatsApp par manual round trip. Reference data aur critical limits doctor se review karwane baaki hain.

## Interview me kaise bolna hai
"M12 me maine lab report explainer banaya. Main LLM ko sirf padhne ke liye use karta hoon — test ka naam, value, unit, lab ki chhapi range. Uske baad sab deterministic hai: unit conversion (lakhs/cumm, mmol/L), range comparison, critical value, trend. Range ke liye lab ki apni printed range ko priority deta hoon kyunki har lab ki method alag hoti hai; fallback range tabhi jab wo padhi na jaye. Reply template se banta hai aur ek verifier check karta hai ki har number data me hai aur koi diagnosis jaisa wording nahi. Critical value kisi bhi cheez se override hoti hai, model ke 'normal' se bhi, aur eval me iska recall 100% gate hai. Medical numbers doctor se review hone baaki hain, ye maine documentation me saaf likha hai."

## Possible interview questions
1. **Report me range na ho toh?** Pehle printed H/L flag, phir `lab_tests` ki fallback range (age/sex ke saath). Age/sex na mile to general adult range aur reply me bolte hain "umar/gender report me nahi mila, isliye general range". Dono na ho to status `unknown` + "lab se pakka karein".
2. **Doctor kehte hain normal, bot keh raha high — conflict?** Bot lab ki apni range se compare karta hai, aur reply me "(lab range …)" dikhata hai, to user dekh sakta hai ki kis range se. Bot kabhi nahi kehta "aapko bimari hai"; hamesha "doctor ko dikhayein". Agar bot ne range galat padhi to `[Galti hai]` se document review me jata hai aur trends se bahar.
3. **Critical value miss ho gayi toh?** Critical check canonical value par chalta hai, lab ke flag ya model ke status par nahi. Low-confidence value par bhi 🚨 aati hai (confirm karne ke note ke saath). Eval ke noisy mode me flag badla, status "normal" likhwaya, confidence giraya — recall phir bhi 100%. Fir bhi limits abhi doctor-reviewed nahi hain.
4. **Hallucinated value kaise pakdi?** Do jagah: runtime verifier har number ko data se match karta hai; eval me alag se **gold page** ke numbers se match hota hai (model ke output se nahi), isliye misread value bhi pakdi jaati hai.
5. **Units kyun deterministic?** Platelets 2.5 lakhs/cumm = 250 ×10³/µL; model se convert karwana risky hai aur har baar alag aa sakta hai. Conversion table `lab_tests.unit_conversions` me hai, test ek jagah.
6. **Trend me "improved/worse" kyun nahi?** Kuch tests me upar jana achha hota hai kuch me bura; judgement doctor ka kaam hai. Hum sirf do values aur dates dikhate hain, aur "ab range ke andar hai" tab jab printed/fallback range se saaf ho.
