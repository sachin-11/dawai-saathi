# M7 — Prescription extraction (F1)

## Is module me kya banaya
User WhatsApp pe prescription ki photo (ya PDF) bhejta hai; bot har dawai ka naam, strength, dose, timing, khane se relation aur duration simple Hindi/English me batata hai. Jo cheez saaf nahi padhi gayi, usse "pharmacist se confirm karein" bolkar alag flag karta hai, guess nahi karta. Gateway `documents` + `medications` rows save karta hai (reminders M10 me inhi se bannege). Pipeline abhi minimal hai (LangGraph M9 me): `classify → extract → validate → gate → compose → verify → save`. Catalog matching, generic suggestion aur reminders is module me **nahi** hain.

## Kyun zaroori tha
Patient handwriting aur dose pattern (`1-0-1`, `TDS`, `AC`) nahi padh paata. Lekin ek galat padha hua dose nuksaan kar sakta hai, isliye design ka center "null is better than a guess" hai: LLM sirf **padhta** hai, baaki sab deterministic code check karta hai, aur jo cheez confident nahi, wo user ko "confirm karo" ke saath dikhti hai.

## Kaise kaam karta hai
```
image/PDF ─► fetch (SSRF-safe presigned URL) ─► PDF? pehle 3 pages render (encrypted/10+ pages reject)
 ─► image_prep: EXIF orientation, RGB, 2000px resize, saara metadata strip, blur/dark/flat check
      └─ bekaar photo? ──► model call SKIP, "achhi roshni me dobara bhejein" tip
 ─► classify_image (CHEAP vision model): prescription | lab_report | medicine_strip | other
 ─► vision_extract_rx (VISION_MODEL, temp 0, strict JSON, per-field confidence; schema fail ─► 1 repair retry)
 ─► redact free-text fields ─► rx_validate (deterministic) ─► confidence gate ─► status done|needs_review|failed
 ─► compose: LLM sirf HAR READABLE dawai ki EK line likhta hai ─► grounding verifier ─► fail ho to j2 template
 ─► reply + disclaimer + 3 buttons  ─► gateway: ek transaction me documents + medications ─► send
```
- **Schema** (`app/schemas/prescription.py`): har value `{value, confidence}`. Patient/doctor name, phone, address, registration no, hospital ke liye field hi **nahi** hai aur `extra="forbid"` hai: model "patient_name" bheje to schema fail. Prompt me bhi explicitly "ignore" likha hai.
- **Validators** (`rx_validate.py`, pure functions): `1-0-1 → 2/din [morning, night]`, `OD/BD/TDS/QID/HS/SOS`, `q6h`, "twice daily", "din me 2 baar", `AC/PC`, "khane ke baad". Model ka derived value written code se ladta ho to **code jeetta hai**, us field ka confidence threshold ke neeche, note add. Range checks: duration 1–365 (galat ho to value hata dete hain), freq ≤ 6/din, tablet dose ≤ 4 (galat ho to flag).
- **Gate** (`rx_gate.py`): name/dose/frequency me se koi missing ya < `EXTRACTION_MIN_CONFIDENCE` (0.75) ⇒ dawai `low_confidence`. Unka naam kabhi dikhaya nahi jaata agar naam hi unclear ho. Document: `done`, `needs_review`, ya `failed` (prescription nahi / unreadable / koi readable naam nahi).
- **Composer**: LLM ko sirf validated structured JSON milta hai (image ya raw OCR nahi, test se assert). Header, unreadable-lines, warnings, disclaimer, buttons hamare templates se aate hain. **Grounding verifier** har LLM line check karta hai: dawai ka naam ho, har number us dawai ke data me ho, Latin words ya to data ke ya chhoti plain-word list ke ho, "stop/side effect/..." jaise advice words na ho. Kuch bhi galat ⇒ `composer_grounding_failed` (sirf reason codes log) aur `rx_reply.{hi,en}.j2` se same data render.
- **Gateway** (`documents/`): `PrescriptionService.save` ek transaction me document + medications; `documents.message_id` UNIQUE ⇒ retry/duplicate pe dobara insert nahi. Low-confidence dawai save hoti hai par `active=false`. Buttons ke ids me `{document_id}` placeholder hota hai, save ke baad gateway asli id daalta hai. `rx:wrong:<id>` ⇒ document `needs_review`, medicines inactive, audit `rx_reported_wrong` (sirf count).

## Important technical decisions
- **LLM padhe, code verify kare.** Pure-LLM se fast build hota, par frequency code jaise table-driven cheezon me code 100% repeatable hai aur test ho sakta hai. Trade-off: rules ki list maintain karni padti hai (naye abbreviations add karne padenge).
- **Composer sirf ek line per dawai likhta hai**, poora reply nahi (spec se zyada strict). Isse "kuch miss ho gaya" ya "extra jaankari" ka raasta band: low-confidence warning LLM pe depend nahi karti.
- **OCR (Tesseract) nahi:** Hindi/English handwriting aur tilted photos par bahut kamzor; structured JSON aur per-field confidence bhi nahi milta. Vision LLM dono deta hai. Trade-off: cost aur latency (20–30 s).
- **Bekaar photo pe model call nahi:** Laplacian-variance blur check (Pillow, no OpenCV dependency). Threshold ko synthetic images par calibrate kiya (sharp ≈ 240, badly blurred ≈ 1, limit 12). Pillow ka kernel filter 1-pixel border copy karta hai, usse variance kharab hoti thi (test me pakda gaya); ab border cut karte hain.
- **Strength/duration out of range = value hata do; dose/frequency out of range = confidence kam.** Kyunki gate sirf name/dose/frequency dekhta hai; impossible duration dikhana galat hai, lekin dose ko human confirm kare.
- **Same dawai do baar:** exact repeat (naam, strength, code, dose, duration) merge; baaki flag (tapering legit ho sakti hai). Pehle sirf naam+code se merge hota tha aur unreadable-dose wali copy chup-chaap gir jaati thi; test se pakda.
- **Fake mode** ek sample prescription deta hai (image nahi dekhta). Real accuracy sirf `make eval-rx MODE=real` se maapi ja sakti hai.

## Production-ready points
- PHI: schema me PHI field nahi, free-text (raw line, instructions, notes) redact hote hain, EXIF/GPS strip, image kabhi disk pe nahi, audit me sirf counts, logs me medicine ka naam nahi.
- Reliability: ek transaction, idempotent save, unique index, concurrent race (`P2002`) handled, AI schema failure par `needs_review`, composer fail par template fallback, PDF limits, decompression-bomb guard.
- Safety: unclear item kabhi guess nahi, generic/reminder abhi "coming soon", "Something is wrong" button medicines band karta hai, doosre user ka document id neutral "not found".
- Tests: ai-service 753 (validators table-driven, image prep, gate, grounding, pipeline, eval gate), gateway 773 unit + 81 integration (signed image webhook → rows + reply, wrong-button, MEDS, idempotency, cascade delete). Eval: `make eval-rx` (fake) CI gate.

## Interview me kaise bolna hai
"Maine WhatsApp pe prescription padhne ka pipeline banaya. Photo pehle preprocess hoti hai (EXIF hatana, resize, blur check — bekaar photo pe LLM call hi nahi). Phir vision LLM strict JSON nikalta hai, har field ke saath confidence. Uske baad deterministic validators: `1-0-1` ya `TDS` jaisa jo likha hai wahi sach maana jaata hai, model ka derived number galat ho to override. Confidence threshold se neeche kuch bhi ho to bot bolta hai 'pharmacist se confirm karein', guess nahi. Reply me LLM sirf structured data ko ek line me phrase karta hai, aur ek verifier check karta hai ki naam aur numbers data se hi aaye hain, warna template fallback. Gateway ek transaction me document aur medicines save karta hai, idempotent."

## Possible interview questions
1. **Handwriting galat padhe toh?** Model ko `null + low confidence` bolne ka instruction hai; gate unhe flag karta hai, naam dikhata hi nahi, medicine `active=false`; user ko "confirm karein". Synthetic eval me scribbled lines ka flag recall 100% gate hai.
2. **Hallucination kaise roka?** Teen layers: schema (extra fields reject), validators (written code beats model), composer verifier (naam/number/words data se). Eval me "hallucination rate" aur "groundedness" gated metrics hain.
3. **Accuracy kitni hai, kaise measure ki?** Honest jawab: fake mode accuracy nahi maapta, sirf pipeline ke safety rules. Real number `make eval-rx MODE=real` se aayega (abhi tak real key ke saath nahi chalaya). Metrics: field accuracy, medicine P/R/F1, hallucination rate, flag recall, PHI leakage.
4. **Cost per prescription?** 3 LLM calls (classify cheap, extract vision, compose text). Real cost abhi pricing.yaml placeholders ki wajah se indicative; bekaar photo pe 0. Eval report me per-document cost aati hai.
5. **OCR (Tesseract) kyun nahi?** Handwriting/Hindi par weak, confidence-per-field nahi, layout samajhna padta. Vision LLM structured output deta hai.
6. **Retry pe duplicate rows kyun nahi?** `documents.message_id` UNIQUE + transaction; race me `P2002` pakad kar existing document return.
