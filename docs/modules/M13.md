# M13 — Voice notes (F7)

## Is module me kya banaya
User WhatsApp par Hindi / English / Hinglish me voice note bhejta hai. Gateway use S3 me rakhta hai, AI service speech-to-text (STT) se text banati hai, aur wo text **wahi graph** chalata hai jo typed text chalata hai — sabse pehle emergency guard. Reply text me aata hai (aur `VOICE ON` ho to chhota voice reply bhi). Nayi cheezein: `app/llm/stt/` (Whisper + Sarvam + fake adapters, router, in-memory ffmpeg), `transcribe` node, Devanagari→Roman copy, shared command table (`packages/contracts/commands/aliases.json`), `detected_command`, "🎧 Aapne poocha" line, `app/llm/tts.py` + `POST /v1/synthesize`, consent v2, `users.voice_replies`, `VOICE ON/OFF`, aur 100 synthetic prompts ka voice eval.

## Kyun zaroori tha
Buzurg aur kam-padhe-likhe users type nahi kar paate. Par voice me teen naye risk aate hain: (1) STT galat sun sakta hai — khaaskar dawai ke naam, (2) "seene me dard" jaisa emergency sentence noise ya low confidence ki wajah se kho sakta hai, (3) transcript ke bharose koi destructive kaam (DELETE) ho jaye. Aur ek privacy sawaal: ab health-related awaaz ek third-party speech service ko jaati hai — consent me ye likhna zaroori hai.

## Kaise kaam karta hai
```
voice note ─► gateway: consent v2? (nahi to ek baar ka notice, STT ko kuch nahi jaata)
           ─► media S3 me ─► (≈10 s se lamba) "🎧 sun raha hoon…" ─► POST /v1/process (input.type=audio)
AI service: transcribe ─► [ffmpeg pipe agar format provider nahi leta] ─► STT router (primary → fallback)
                       ─► raw_text (jaisa mila) + roman_text (Devanagari→Roman copy)
            emergency_guard (DONO scripts, low-confidence/partial text par bhi) ─► redact ─► emergency_classifier
            unclear? ─► "dobara bolo / type karo" (emergency check ke BAAD)
            classify: pehle command table (poora utterance) ─► nahi to intent ─► purane branches (generic, interaction, lab)
            reply = "🎧 Aapne poocha: “…”" + jawab  (sirf medical sawaalon par, emergency par nahi)
gateway: detected_command? ─► typed command jaisa hi chalao (DELETE = sirf button) ; nahi to reply bhejo
         VOICE ON? ─► spoken_text ─► POST /v1/synthesize ─► Graph API upload ─► audio message (text ke BAAD)
```
- **Intake** (gateway): `audio/amr` allowlist me jodi. Meta webhook me duration nahi aati, isliye "listening" message file size se guess hota hai (> ~20 KB ≈ 10 s). Asli limit `MAX_AUDIO_SECONDS` (120) AI service lagati hai: ogg/opus ka duration Ogg granule se, baaki formats ka ffmpeg decode se. Limit se lamba note STT ko jaata hi nahi — "chhota note bhejo" template.
- **STT layer**: `STTProvider` protocol → `WhisperProvider` (OpenAI `/audio/transcriptions`), `SarvamProvider` (`/speech-to-text`, header `api-subscription-key`), `FakeSTTProvider`. `STTRouter` M5 jaisa: jitter retry, circuit breaker, fallback sirf timeout/429/5xx/connection par (bad credentials ya undecodable audio par nahi). Sarvam REST chhote clips ke liye hai (docs: "under 30 seconds"), isliye `STT_SARVAM_MAX_S` se lambe note par router use skip karke dusre provider ko deta hai.
- **ffmpeg, bina disk**: `ffmpeg -i pipe:0 -f s16le pipe:1` → PCM; WAV header hum khud likhte hain (pipe par ffmpeg size wapas nahi likh sakta), aur PCM ki lambai = exact duration. Test assert karta hai ki `tempfile` kabhi nahi chalti aur command me sirf `pipe:0/pipe:1` hai. Docker image me `ffmpeg` install hai.
- **Script policy**: `raw_text` jaisa provider ne diya (Devanagari ya Roman) + `roman_text` (rule-based transliteration, `app/safety/translit.py`, sirf matching ke liye, user ko nahi dikhta). Emergency rules **dono** par chalte hain; intent/extractor models Roman copy (redacted) dekhte hain; "Aapne poocha" line original script me (redacted, ≤ 120 chars).
- **Emergency pehle**: `transcript_user_texts()` transcript se `UserText` banane ka akela raasta hai (image se kabhi nahi). Empty/short/low-confidence transcript bhi guard se guzarta hai; sirf guard aur classifier ke baad "dobara bolo" jaata hai. STT poori tarah down ho to reply me 112/108 likha hota hai.
- **Commands by voice**: alias table ab ek shared file hai; gateway typed text ke liye, AI service transcript ke liye. Poora utterance match hota hai (filler "please", "ji" hata kar), "mujhe apni dawai ke baare me poochna hai" command nahi. Voice me caregiver commands aur bare "haan/nahi" kabhi detect nahi hote. `le li` → `reminder_taken` → gateway wahi 2-ghante wala `latestOpenSlot` rule lagata hai.
- **DELETE by voice**: AI service sirf `detected_command=delete` deti hai; gateway `deletion.request()` chalata hai jo **button** bhejta hai. Transcript akela kabhi kuch delete nahi karta.
- **Dawai ke naam**: voice se aaya naam catalog se confident match na kare to jawab nahi — "naam type karo ya photo bhejo". Interaction sawaal me naam kisi product ya known salt se bhi match na kare to wahi.
- **TTS** (`TTS_ENABLED`, default false, aur user ka `VOICE ON`): `build_spoken_text()` tay karta hai kya bola jaye — interaction jawab aur lab-test sawaal poora (≤ 600 chars ≈ 40 s), prescription aur lab report ka chhota summary (count + readable dawai ke naam + "poori detail text me", critical ho to "aaj hi doctor"). **Kabhi nahi**: emergency, generic price list, help/greeting, command ka jawab, verifier fail. Text reply hamesha pehle jaata hai; audio best-effort hai (fail ho to log + user ke paas text hai). Vendor WAV deta hai (Sarvam ke docs me ogg nahi, `opus` validation error deta hai), ffmpeg use mono Ogg/Opus me badalta hai, 45 s se lamba ho to refuse. Audio S3 me store nahi hota; gateway upload ke baad sirf media id queue me daalta hai (naya `audio` outbound kind).
- **Consent v2**: `CONSENT_VERSION='v2'`, naya text speech service batata hai. Purane (v1) user ke pehle voice note par ek baar chhota notice + `[Haan, sahmat hoon] [Main likhunga]`; tab tak na download, na STT. "Haan" par `consent_version=v2`, audit `consent_updated`, user se note dobara bhejne ko kaha jaata hai (purana note process nahi hota, jaan-boojh kar).

## Important technical decisions
- **Wahi graph, naya input**: alag voice pipeline nahi. Fayda: emergency guard, redaction, intent, branches, verifier sab free. Trade-off: STT ki galtiyan seedhe aage jaati hain, isliye drug-name rule aur "Aapne poocha" line.
- **Sarvam ka `language_probability` confidence nahi**: wo language detect ki probability hai, speech accuracy nahi. Isliye Sarvam results me `confidence=None`; low-confidence gate sirf Whisper (segment `avg_logprob × (1 − no_speech_prob)`) aur text-length par chalta hai. Honest limitation.
- **Command table shared file**: ek jagah, do apps, stale-copy test dono me. Voice-only aliases ("meds dikhao", "awaaz me jawab do") typed me bhi chalte hain.
- **Fail-safe ordering**: emergency stage 1 → redact → stage 2 → tab "unclear". Eval ne ek bug pakda: `"ले ली"` ko "bahut chhota" maana ja raha tha kyunki matras (combining marks) gine nahi ja rahe the; ab L/N/M categories gini jaati hain.
- **TTS gateway se upload, queue me media id**: audio bytes Redis me nahi (PHI rule), retry/dedupe queue se milta hai.
- **Direct test-time fake**: `FakeSTTProvider` "audio" = `FAKEAUDIO\n{json}` bytes; asli audio refuse karta hai, taaki fake mode kabhi jhoothi sunai na de.

## Interview me kaise bolna hai
"M13 me maine voice notes jode, bina naya pipeline banaye. Voice note ek STT router se text banta hai — Whisper primary, Sarvam fallback, jitter retry aur circuit breaker ke saath — aur phir wahi LangGraph chalta hai jo typed text ke liye hai, emergency guard pehle. Hindi transcript ke liye main Devanagari aur uski Roman copy dono par emergency rules chalata hoon, aur low-confidence transcript par bhi pehle emergency check, phir 'dobara bolo'. STT dawai ke naam galat sun sakta hai, isliye confident catalog match na ho to jawab nahi deta, aur har medical jawab 'Aapne poocha: …' se shuru hota hai. DELETE voice se detect hota hai par gateway hamesha button confirmation maangta hai. Eval me 44 emergency voice prompts par 100% recall hard gate hai, noisy aur low-confidence transcripts ke saath bhi. Honest limit: synthetic TTS audio asli buzurg awaaz se aasaan hai, isliye real-user recording ka plan alag hai."

## Possible interview questions
1. **STT galat drug naam sune toh?** Naam catalog se ≥ 0.8 confident match na kare to koi generic/interaction jawab nahi; user se naam type karne ya photo bhejne ko kehte hain. Jo jawab dete hain wo "Aapne poocha: …" se shuru hota hai taaki user galti pakad le. Eval me 5 misheard names par 0 answered.
2. **Background noise me kya?** Noise ya low confidence par transcript "unclear" ho sakta hai — par pehle emergency guard us partial text par chalta hai. Eval ke noisy mode me emergency prompts jaan-boojh kar low confidence (0.1) par bheje gaye; recall 44/44 raha. Asli noise par accuracy provider par depend karti hai — real-mode eval se naapni hai.
3. **Kitna latency aata hai?** Fake mode me ~ms. Real latency `make eval-voice MODE=real` ka p50/p95 batayega (maine abhi chalaya nahi). Design me: download + (optional ffmpeg) + ek STT call (timeout 25 s, 2 attempts) + normal graph; ">10 s" note par user ko "sun raha hoon" turant milta hai.
4. **Real buzurg users ki awaaz par accuracy?** Pata nahi — synthetic eval TTS awaaz se bana hai jo saaf aur regular hoti hai. Plan: family/friends ki consent se chhoti recording set (local, kabhi commit nahi, run ke baad delete), wahi `run_voice_eval.py` se.
5. **DELETE voice se kyun nahi?** Ek mis-transcribed "delete" poora data mita sakta hai. Isliye transcript sirf `detected_command` banata hai; erasure sirf button confirm par (5 min window).
6. **Whisper vs Sarvam kyun dono?** Whisper general-purpose aur lambe clips ke liye; Sarvam Indian languages aur Hinglish code-mixing ke liye design hui (`mode=codemix`, saaras:v3). Dono ek hi eval table me compare hote hain (`--providers whisper,sarvam`); numbers abhi measure nahi kiye.
