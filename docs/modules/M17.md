# M17 — AWS deployment (EC2 + Docker Compose, demo mode)

> Status: code, Terraform, CI/CD and docs are written and statically checked. **Nothing has been applied to AWS yet**,
> so the smoke tests, alarm test, rollback test and restore drill below are still open (see `docs/runbooks/go-live.md`, steps 6-9).

## Is module me kya banaya
Ek hi EC2 instance (`t4g.medium`, Mumbai) par poora app Docker Compose se chalta hai: Caddy (HTTPS), gateway-api, gateway-worker,
ai-service, web, Redis aur Postgres. Terraform se VPC, EC2, S3, ECR, IAM, Route 53, alarms aur budget guard banta hai. GitHub Actions
tag par images banata hai, ECR me SHA tag se push karta hai aur SSM se instance par `deploy.sh` chalata hai. Health check fail hua to
khud purane SHA par rollback. Poora setup **~$10/month** ke andar rakhne ke liye "demo mode" hai: instance sirf zarurat par start hota hai.

## Kyun zaroori tha
Local `docker-compose` se WhatsApp webhook public HTTPS URL nahi ban sakta, aur Meta ko ek real URL chahiye. Personal AWS account me
ECS + RDS + ALB + NAT ka bill (~$100+) possible nahi tha, isliye sabse sasta raasta chuna jo baad me ECS/EKS par ja sake
(containers aur Terraform wahi rahenge).

## Kaise kaam karta hai
```
git tag v* -> deploy.yml: CI (tests + eval gates) -> arm64 images -> ECR (tag = git SHA) -> Trivy
   -> release bundle S3 (compose, Caddyfile, scripts) -> SSM: DESIRED_SHA -> SSM Run Command -> deploy.sh <sha>
deploy.sh: render .env (SSM) -> pull -> [snapshot agar nayi migration] -> migrate -> ai -> api+web -> caddy -> worker (last)
           -> health + smoke -> fail? rollback to PREVIOUS_SHA, FAILED_SHA likh do, exit 1
boot: DNS (Route 53 me naya IP) -> dawai.service (CURRENT ya DESIRED release start) -> 3 ghante baad auto-stop
stop: ExecStop = pg_dump + redis dump S3 me, phir containers graceful stop
```
Cost guard: Budget alert 50/80/100%, $8 par Budget Action instance STOP karta hai, har boot par 3-ghante ka timer, aur `make start`
Cost Explorer se is mahine ka kharcha dekhkar $10 par start refuse karta hai (agle mahine apne aap khulta hai).

## Important technical decisions
| Decision | Reason / trade-off |
|---|---|
| EC2 + Compose, ECS Fargate nahi | Fargate + ALB + NAT + RDS + ElastiCache ~$100+/month; ek instance ~$30-60 always-on, demo mode me ~$10. Trade-off: single point of failure. Path to ECS: images + env + health checks pehle se containerised hain, Terraform me sirf compute module badlega |
| Postgres container me, RDS nahi (abhi) | RDS ka fixed kharcha ~$15-20 aur stopped RDS 7 din baad khud start ho jata hai. Trade-off: PITR nahi, patching hamari zimmedari. `docs/runbooks/rds-upgrade.md` me migration plan |
| Redis container, `noeviction`, AOF | Queue ke jobs evict nahi hone chahiye; 128 MB maxmemory; nightly + stop par dump |
| Graviton (`t4g`, arm64) | ~20% sasta; images `linux/arm64` build hote hain (QEMU ya `BUILD_RUNNER=ubuntu-24.04-arm`). Wheels (spaCy, pypdfium2, sharp, prisma) arm64 par pehli CI run me confirm karni hain |
| Elastic IP nahi, boot par Route 53 update | EIP ~$3.6/month deta even when stopped; delegated subdomain `dawai.rasuonline.in` (sirf 4 NS records GoDaddy me, baaki domain safe) |
| Secrets: SSM Parameter Store SecureString, Secrets Manager nahi | Secrets Manager $0.40/secret/month; SSM standard free. Terraform kabhi secret value nahi likhta (state me plaintext na jaye) |
| No SSH, SSM Session Manager | Koi key/port 22 nahi; access IAM + CloudTrail se |
| GitHub OIDC | GitHub me koi AWS key nahi; role sirf is repo ke `v*` tags/main ko trust karta hai |
| ECR tags immutable, SHA se pin | Ek SHA ka image kabhi badalta nahi, rollback exact wahi image deta hai |
| Migrations expand -> migrate -> contract | Rollback me purana code migrated DB par chalta hai (CLAUDE.md §10) |
| Terraform state: S3 + native lockfile | DynamoDB table ki zarurat nahi (Terraform >= 1.10); spec se chhota deviation |
| OTel collector optional (profile `obs`), logs awslogs driver se CloudWatch | 4 GB instance par extra containers nahi; M15 ke Prometheus alerts yahan deploy nahi hain |

## Production-ready points
- **Security:** SG sirf 80/443; IMDSv2; EBS/S3/ECR encrypted; least-privilege IAM; non-root, read-only containers, `no-new-privileges`; Caddy HSTS aur
  headers, access log me query/secret headers redact; boot guards (gateway env schema + AI settings + `render-env.sh`) placeholder, `LLM_MODE=fake`,
  http URLs, dev flags refuse karte hain. Details: `docs/security.md`.
- **Reliability:** healthchecks, `restart: unless-stopped`, worker last, graceful stop (40 s), auto-rollback, snapshot before migration.
- **Tested here (static):** `terraform validate` (stack + bootstrap), `docker compose config`, `bash -n` on all scripts, gateway env-guard unit tests (55 pass),
  Docker builds of the gateway (runtime + migrate) and web images (see "Not verified" for results).
- **CI:** new `infra` job (terraform fmt/validate, tflint, checkov, shellcheck, compose config) and `deploy.yml` (OIDC, buildx, Trivy).

## Limitations (honest)
- **Single instance:** if it dies, the site and the WhatsApp bot are down until you rebuild (runbook D, target < 1 hour, **not yet measured**).
  A deploy restarts containers (a few seconds of downtime, no blue/green). Scaling is vertical (bigger instance).
- **Demo mode = bot is off when the instance is stopped.** Meta retries webhooks for a while, but reminders do not fire while it is down.
- **Budgets are not hard caps** (cost data lags up to a day): hence $8 stop threshold plus the 3-hour boot limit.
- **Container Postgres:** no point-in-time recovery; a restore loses data since the last dump.
- **Mitigation plan:** nightly dumps + dump on every stop, Terraform rebuild, move to RDS, then a second instance behind an ALB, then ECS.

## Interview me kaise bolna hai
"Maine Dawai Saathi ko ek EC2 instance par Docker Compose se deploy kiya, Terraform se. Caddy automatic HTTPS deta hai, secrets SSM Parameter Store me hain
aur instance role se padhe jate hain, koi access key nahi. GitHub Actions OIDC se AWS me login karta hai, images git SHA se ECR me jaati hain aur SSM se deploy hota
hai, SSH nahi. Deploy health check fail hone par khud rollback karta hai, aur migrations backward compatible rakhi hain taaki rollback safe ho. Personal account ke
budget ke liye demo mode banaya: instance zarurat par start hota hai, auto-stop aur budget action se bill $10 ke andar rehta hai. Limitation single point of failure hai;
agla step RDS, phir ALB ke peeche do instances, phir ECS."

## Possible interview questions
1. **EC2 down ho jaye toh?** CloudWatch status-check alarm e-mail deta hai; disk bacha ho to reboot/start; nahi to Terraform + SSM secrets + last SHA se rebuild (`restore.md`), database dump S3 se. Redis ke reminder jobs planner 15 min me rebuild karta hai.
2. **Zero-downtime deploy kaise?** Abhi nahi: ek instance par containers recreate hote hain (kuch second). Fix: ALB + 2 instances rolling, ya ECS rolling update; app stateless hai aur migrations backward compatible, isliye possible hai.
3. **10x traffic par scale?** Pehle bottleneck LLM calls aur AI service memory: instance badhao (`t4g.large/xlarge`), workers alag container me pehle se hain, phir RDS, Redis ElastiCache, ECS me alag services.
4. **Secrets kaise manage kiye?** SSM SecureString, instance role se `get-parameters-by-path`, `.env` root-only 600 deploy par render hota hai, Terraform state me value nahi, GitHub me AWS key nahi (OIDC).
5. **ECS kyun nahi?** Cost aur simplicity: ECS + ALB + NAT + RDS ~$100+ vs ek instance. Containers, health checks, env-from-secrets pehle se ECS-ready hain.
6. **Rollback kaise safe hai?** Image SHA se pinned aur immutable, purani release bundle S3 me, migrations expand/contract, rollback migrate nahi chalata.
