# M0 — Repo bootstrap

## Is module me kya banaya
Poora project ka "ghar" taiyaar kiya: ek monorepo (pnpm workspaces + Turborepo) jisme NestJS gateway (`apps/gateway`) aur FastAPI AI service (`apps/ai-service`) ke khaali skeleton hain. Dono me config validation, structured logging, request-id, error format aur `/health/live` endpoint hai. Saath me lint/format, git hooks, Makefile, Dockerfiles aur GitHub Actions CI bhi set hai. Koi business logic ya WhatsApp code nahi hai.

## Kyun zaroori tha
Agar shuru me tooling, conventions aur CI na ho, to har naya module alag style me banega aur baad me sab todna padega. M0 se har module ko ek jaisa base milta hai: same env rules, same log format, same error body, same lint rules. Isse bugs jaldi pakde jaate hain aur team (ya interviewer) ko code predictable lagta hai.

## Kaise kaam karta hai
```
make dev
  └─ turbo run dev
       ├─ apps/gateway     (NestJS, :3000)
       └─ apps/ai-service  (uvicorn app.main:create_app --factory, :8000)

Request ──► request-id middleware ──► route ──► JSON access log (method, path, status)
                                         └─ error? ──► same body: {error:{status,code,message,request_id}}

Boot ──► .env load ──► zod / pydantic-settings validate ──► missing/invalid? crash with clear message
```
1. `make install` dependencies lagata hai (`pnpm install`, `uv sync`) aur husky hooks install karta hai.
2. Commit par `lint-staged` changed files par ESLint/Prettier/ruff chalata hai; `commitlint` conventional commit message check karta hai.
3. Push par GitHub Actions (`.github/workflows/ci.yml`) gateway aur ai-service ke lint + typecheck + test alag jobs me chalata hai.

## Important technical decisions
- **pnpm + Turborepo, ai-service ke liye `uv`**: Node aur Python ek repo me, ai-service ka chhota `package.json` `uv run ...` call karta hai taaki Turborepo dono ko orchestrate kare. Trade-off: thoda extra wrapper, lekin `make dev` ek command me dono chalata hai.
- **NestJS 11 + nestjs-pino 4, TypeScript ~6.0, CommonJS**: NestJS 12 sirf ESM hai aur Jest ke saath tootta hai. Compatibility ke liye pin kiya, Decisions Log me reason likha hai.
- **Env validation boot par (zod 4 / pydantic-settings)**: galat config ho to app start hi na ho (fail fast). Error me variable ka naam aata hai, value kabhi nahi (secret leak se bachne ke liye). `NODE_ENV=production` me placeholder `SERVICE_TOKEN=change-me` reject hota hai.
- **App factory in FastAPI (`create_app`)**: import par side effect nahi, tests apni settings inject kar sakte hain.
- **Ek jaisa error body dono apps me**: client ko ek hi format handle karna padta hai; internal error message bahar nahi jaata.
- **Request id**: safe inbound `x-request-id` reuse hota hai warna UUID; response me wapas aata hai. Regex `[A-Za-z0-9._-]{1,128}` se log injection rokta hai.
- **Logs me sirf method + path + status**: body aur query string nahi, auth/signature headers redacted. Ye PHI protection (CLAUDE.md §2.6) ka pehla step hai.
- **`.gitattributes` se LF force**: Windows par CRLF ki wajah se Prettier/ruff check fail na ho.

## Production-ready points
- Security: default secret production me reject, headers redacted, non-root Docker user.
- Reliability: Dockerfiles me `HEALTHCHECK`; gateway image `pnpm deploy --prod` se minimal banti hai.
- Quality gates: ESLint + Prettier, ruff, `tsc` strict, `mypy --strict`, pre-commit hook, commitlint, CI.
- Testing: gateway me 12 unit + 5 e2e (Jest), ai-service me 15 pytest. Config validation, health endpoint, error body aur request-id ke tests.
- Honest gap: Docker image abhi poori tarah build-verify nahi hui thi (Docker daemon band tha); CI ka pehla run push ke baad dekhna hai.

## Interview me kaise bolna hai
"Maine Dawai Saathi ko monorepo me start kiya: NestJS gateway aur FastAPI AI service, pnpm aur Turborepo se orchestrate. Pehle module me hi maine foundation pakka kiya: env variables boot par validate hote hain, logs structured JSON me hain jisme koi phone number ya body nahi jaata, dono services ka error format same hai, aur har request ka request-id trace hota hai. Commit par lint aur conventional-commit check hota hai, aur CI har push par dono apps ke lint, typecheck aur tests chalata hai. Healthcare data hone ki wajah se privacy aur fail-fast behaviour maine shuru se hi design me rakha."

## Possible interview questions
1. **Monorepo kyun?** Gateway aur AI service ke contracts sync me rakhna aasan hai, ek PR me dono badal sakte hain, aur CI/tooling ek hi jagah hai. Trade-off: build tooling thodi complex.
2. **Do alag services kyun (NestJS + FastAPI)?** User state aur WhatsApp I/O gateway ke paas hai; AI (LangGraph, Python ecosystem) stateless service me hai. Isse AI independently scale/test ho sakta hai.
3. **Fail-fast config ka fayda?** Galat config production me chupke se chalne ke bajay deploy time par hi pakda jaata hai. Variable ka naam dikhta hai, value nahi.
4. **Logs me PHI kaise rokte ho?** Body/query log hi nahi karte, sensitive headers redact, aur phone numbers/OCR text kabhi log nahi hote. Pino/structlog JSON format.
5. **NestJS 12 kyun nahi?** ESM-only hai, Jest ke CJS runtime ke saath problem; Node 20 par nestjs-pino 5 bhi nahi chalta. Version pin + Decisions Log entry.
6. **CI me kya chalta hai?** Format check, lint, typecheck, tests, build (gateway) aur ruff, mypy, pytest (ai-service), alag jobs me parallel.
