# M8 — Medicine catalog + Generic Finder (F2)

## Is module me kya banaya
Prescription ki har dawai ko catalog (`drugs` table) se match karta hai (salt, strength, form, release type), aur sirf tab sasta generic / Jan Aushadhi vikalp batata hai jab **salt + strength + form + release type chaaron bilkul same** ho. Ingestion scripts (`make seed`), normalisers (salt/strength/form), matcher (exact → salt → trigram → vector), generic finder, `no_substitute.yaml` exclusion list, "Generic medicines" button, aur text query "Dolo 650 ka generic batao" bana. Sab deterministic code hai: LLM kabhi salt ya price decide nahi karta.

## Kyun zaroori tha
Branded dawai mehngi hoti hai, par galat generic (galat strength, SR ki jagah plain, thyroid/warfarin jaisi NTI dawai) nuksaan kar sakta hai. Isliye feature ka asli kaam "suggest karna" nahi, balki **galat suggest na karna** hai. Aur data sach me problem hai: koi licensed brand dataset nahi mila, to system aise design hua ki jo catalog load ho usi par chale, aur gap honestly document hai (`data/SOURCES.md`).

## Kaise kaam karta hai
```
M7 extraction ─► validate ─► normalize_drugs (match) ─► generic_finder ─► confidence gate ─► compose ─► reply
                                 │                          │
   brand name ─► brand_key       │   4-key exact lookup ◄───┘ + exclusions + savings
   1 exact  (dolo650)            │
   2 salt written (Metformin 500 mg → salt_key + strength_key)
   3 trigram / prefix (pg_trgm, "Pentop 40", "डोलो")
   4 vector fallback (Pinecone / in-memory), 5 none
```
- **Keys** (`app/catalog/normalise.py`, ek hi code ingestion aur matcher dono me): `salt_key` (sorted INN `+`), `strength_key` (`650mg`, `125mg/5ml`, `500mg+125mg`), `form_key`, `release_type` (`ir/sr/er/xr/cr/mr/dr/na`).
- **Matcher**: strength jo prescription me likha hai wo hamesha catalog se upar. Mismatch ⇒ `strength_conflict`, finder refuse. Strength verified tabhi maana jaata hai jab prescription me likhi ho, ya brand ke naam ka number (Dolo **650**) catalog strength se match kare. Do products barabar fit hon ⇒ `ambiguous`, sirf wahi bataya jo sab candidates me common ho (aksar salt).
- **Finder**: low-confidence line, weak match (<0.8), conflict, ambiguity, unverified strength, exclusion list ⇒ koi suggestion nahi, `reason_if_none` ke saath. Phir 4-key exact query, apna product hataya, cheapest first (Jan Aushadhi agar cheapest ke 10% ke andar), max 2, `MIN_SAVINGS_PCT` 15%.
- **Savings** = `(brand price/unit − alt price/unit) × units_needed` (dose × freq × days), warna per-pack. **Sirf tab jab dono prices maloom ho.** Brand price unknown ho to "sasta" kabhi nahi bolte, sirf "same salt ka generic available hai".
- **Reply**: main reply me ek line per dawai (template, LLM nahi). Button `rx:generic:<id>` ⇒ gateway stored suggestions `/v1/generic-details` ko bhejta hai, AI service templates se render karti hai (`generic_details.j2`), aur verifier har ₹ amount aur brand name data se check karta hai.

## Important technical decisions
- **4-key exact rule + exclusions** (`app/safety/no_substitute.yaml`): modified-release sab excluded (spec ke hisaab se, `dr` bhi, jab tak pharmacist na bole), NTI, insulin/biologics, inhaler, `form_key=other`. Trade-off: pantoprazole (gastro-resistant) jaisi common dawai ka generic nahi milta. Safe galti > missed saving.
- **Conservative salt stripping**: sirf listed names (`amlodipine besylate`→`amlodipine`, `pantoprazole sodium`…). `diclofenac sodium` vs `potassium` alag rakhe. Galat strip = galat suggestion; missing strip = sirf missed suggestion.
- **Salt stage trigram se pehle** (spec ke order se alag): "paracetamol" jaisa generic naam kisi brand se fuzzy match na ho.
- **Release-word mismatch fuzzy stage me conflict**: plain prescription "Metformin" "Metformin SR" brand se jud na jaye. Ye eval me gap dikha tha, fix kiya.
- **Prefix stage**: spec me `डोलो` match hona tha, par trigram 0.44 tha (threshold 0.45 se zara kam). Prefix match se family mili (ambiguous, salt known, score < 0.8 ⇒ generic kabhi nahi).
- **Pinecone interface ke peeche**, local me in-memory + hashing embedder (offline). Pinecone/embedding API sirf mocked HTTP se test hui.
- **Matcher/finder LLM-free**; LLM sirf typed query me naam copy karta hai (`generic_query_extract_v1`).
- **Parity test**: Postgres (pg_trgm) aur in-memory repository same results dete hain, aur poora eval real DB par bhi chala.

## Production-ready points
- Safety: 4 hard gates eval me **0** (wrong-strength, wrong-form/release, wrong-salt, forbidden suggestion) — pytest + CI dono me fail karte hain. Gate khud test hota hai (jaan-boojh kar galat suggestion daalo to fail).
- Bugs jo eval/tests ne pakde: `parse_money("Rs. 30")` ₹0.30 de raha tha (100x galat price), Devanagari matras `_clean_name` me kat jaate the, salt stage release "na" maan kar sab filter kar deta tha, plain↔SR fuzzy mismatch.
- Data: idempotent upsert `(source, source_ref)`, har row me `source` aur `price_source_date`, rejected rows ka report, fixture production me refuse, raw/brand data gitignored.
- Catalog down ho to reply M7 jaisa chalta hai (`catalog_unavailable`), request fail nahi hoti. AI service read-only role se padhti hai (`salt_aliases` par bhi sirf SELECT).

## Interview me kaise bolna hai
"Maine generic finder banaya jo galat suggestion se bachne par focus karta hai. Prescription ki dawai ko normalised keys me badalta hoon: salt, strength, form, release type. Matching deterministic hai — exact brand, phir generic naam, phir fuzzy trigram, phir vector fallback — LLM salt decide nahi karta. Suggestion tab jab chaaron keys bilkul same hon, strength confirmed ho, aur dawai exclusion list me na ho (thyroid, warfarin jaisi NTI, SR products, insulin). Savings tabhi bolta hoon jab dono prices maloom ho. 279 synthetic cases ka eval hai jisme wrong-strength, wrong-form aur forbidden suggestion zero hone chahiye, aur CI me gate hai."

## Possible interview questions
1. **Galat generic suggest ho gaya toh?** Teen layers: matcher conflict/ambiguity flag karta hai, finder 4-key exact + exclusions lagata hai (defence in depth: repository galat rows de to bhi filter), eval gate CI me. Phir bhi reply me "doctor/pharmacist se poochkar hi badlein".
2. **Pinecone kyun, sirf Postgres se kaam nahi chalta?** Trigram typos pakadta hai, par semantic/transliteration cases me weak. Isliye vector sirf fallback hai, interface ke peeche; local me Postgres+in-memory kaafi hai. Honestly: real embeddings abhi test nahi hue.
3. **Price data purana ho toh?** Har price ke saath `price_source_date`, reply me "approximate MRP, date tak ki" likha hota hai, `make seed` idempotent hai (nayi list daalo). Pricing refresh process abhi manual hai.
4. **Brand name galat spelling me ho toh?** `brand_key` (lowercase alnum), exact, phir pg_trgm similarity ≥ 0.45, prefix, vector. Eval: typo cases ~95% sahi match, baaki abstain (kabhi galat product nahi).
5. **Brand dataset ka licence?** Koi verified nahi mila, isliye commit nahi kiya; curated list (apni, unreviewed) + optional local CSV. Gap `data/SOURCES.md` me likha hai, aur savings tabhi dikhti hai jab brand price ho.
6. **Salt stripping kyun conservative?** `amlodipine besylate`→`amlodipine` safe hai, par `diclofenac sodium`/`potassium` ya `metoprolol succinate`/`tartrate` alag hain. Galat merge = galat suggestion.
