# M16 — Web app: landing, demo playground, admin

## Is module me kya banaya

`apps/web` (Next.js 15) banaya: ek landing page (Hindi default, English at `/en`), privacy + terms pages, ek **live demo playground** jahan koi bhi sample prescription/lab report par asli AI pipeline chala ke dekh sakta hai (extraction, confidence, generics, warnings, WhatsApp-style reply, LangGraph trace), aur ek **admin dashboard** (stats, review queue, evals, prompts, DLQ, budget). Gateway me iske liye do naye APIs bane: `POST /demo/process` aur `/admin/*`.

## Kyun zaroori tha

Product WhatsApp par hai, lekin:

- **Reviewer/recruiter** ke paas tumhara WhatsApp number nahi hota. Unhe browser me 30 second me dikhna chahiye ki system kya karta hai. Trace view se pipeline "dikhta" hai.
- **Meta business verification** ko ek public website + privacy policy + terms chahiye.
- **Operations**: review queue, DLQ retry, budget, eval reports ek jagah. Lekin patient data by default chhupa rehna chahiye.

## Kaise kaam karta hai

```
Browser ──► Next.js route handler (server) ──► Gateway ──► AI service
 (no token)   /api/demo, /api/admin/*          /demo/*       /v1/process
                                               /admin/*      (DEMO_SERVICE_TOKEN)
```

1. **Demo, sample**: browser `sample_id` bhejta hai → BFF (`app/api/demo/route.ts`) gateway ko `X-Demo-Key` ke saath call karta hai → gateway **cache** se jawab deta hai (`apps/gateway/demo-cache/<sample>.<lang>.json`). Koi model call nahi, koi upload nahi, kharcha zero. `make demo-cache` ye files banata hai (poori pipeline se, trace ke saath).
2. **Demo, upload**: checkbox tick → browser canvas se image chhoti karta hai (EXIF hat jata hai) → BFF → gateway: IP rate limit (10/ghanta, 30/din) → demo budget check → Turnstile verify → magic-byte sniff + `sharp` se re-encode (EXIF server par bhi hat jata hai) → S3 `demo/` prefix → presigned URL → AI service (`DEMO_SERVICE_TOKEN`, `include_trace: true`) → jawab + `debug_trace` → file turant delete (24 ghante ka lifecycle rule sirf backstop). `documents`/`messages`/`medications` me **kuch nahi** likha jata.
3. **Admin**: NextAuth (GitHub OAuth, `ADMIN_EMAILS` allowlist, 30 min session) → har gateway call par Next.js server 5-minute ka HS256 JWT sign karta hai → gateway signature, expiry, audience aur allowlist **dobara** check karta hai.
4. **Reveal**: review list me sirf metadata aur gini hui "unclear items" hoti hain. "Reveal" ke liye reason (10+ chars) likhna padta hai → gateway **pehle** `audit_logs` me `admin_reveal` (email, document id, reason) likhta hai, phir hi extraction + 60-second ka image link deta hai. Image link browser tak nahi jata: Next.js server image fetch karke `data:` URL me inline kar deta hai.

## Important technical decisions

| Decision | Reason / trade-off |
|----------|--------------------|
| BFF pattern: browser kabhi gateway/AI service/token nahi dekhta | Public site par koi token leak na ho. Test: `tests/security.test.ts` (client code me server module import nahi), `scripts/scan-bundle.mjs` (bundle me secret value nahi), Playwright (page me demo key nahi) |
| Sample = cache only | Budget khatam ho tab bhi demo chalta hai; "bill na bhage" ka sabse seedha jawab. Trade-off: cache fake-model se bana hai jab tak real keys na ho (UI model name dikhata hai) |
| Demo ka alag budget (`budget:demo:<day>`) | Demo par flood aaye to asli users ka budget na khaye |
| Turnstile production me missing ho to uploads **band** (fail closed) | Bot protection ke bina public upload khulna nahi chahiye; samples phir bhi chalte hain |
| JWT khud likha (`node:crypto`), sirf HS256 | Koi library misconfiguration nahi; `alg: none` / algorithm confusion test se pakde jaate hain |
| Admin audit me email allowed (`logAdmin`) | Operator patient nahi hai; "kisne kya dekha" audit ka maqsad hai. Baaki metadata pehle jaisa machine-token-only hai. Reason redacted + 300 chars cap |
| Next.js middleware me nonce wala CSP, `strict-dynamic` | Scripts par `unsafe-inline` nahi. Trade-off: pages dynamic render hote hain |
| Hindi `/` par, English `/en` par (apna chhota middleware, next-intl messages ke liye) | URL saaf; `/hi/...` 308 se `/...` par jata hai |
| Architecture diagram `docs/architecture/graph.mmd` se build time par SVG me banta hai | Code se drift nahi ho sakta; client JS nahi |
| Landing ke eval numbers `evals/reports/*.json` se build time par | Marketing claims nahi, asli report. Page saaf likhta hai ki ye fake-model run hai |
| Auth.js v4 (stable), v5 beta nahi | Stable version; GitHub provider kaafi hai |

## Production-ready points

- **Security headers**: CSP (nonce), `X-Frame-Options: DENY`, HSTS (prod), Referrer-Policy, Permissions-Policy, `poweredByHeader` off.
- **PHI**: admin response me phone number kabhi nahi (integration test regex se check karta hai). Demo logs me sirf request id, intent, latency. IP sirf keyed hash banke rate limit ke liye, 1 din tak.
- **Tests**: Vitest (web), Jest unit + e2e + integration (gateway, asli Postgres/Redis/MinIO), Playwright + axe (asli stack, fake providers), Lighthouse CI.
- **Rate limit + budget**: M15 ka sliding window reuse; admin per-email 120/min.
- **Privacy/Terms**: system jo asal me karta hai usse likhe gaye; **draft hain, legal review baaki** (page par banner + code me comment).

## Interview me kaise bolna hai

"Product WhatsApp par hai, to mene ek Next.js app banayi jo teen kaam karti hai: landing aur privacy pages jo Meta verification ke liye chahiye, ek live demo jahan koi bhi sample document par poori LangGraph pipeline chala ke trace dekh sakta hai, aur ek admin dashboard. Sabse zaroori design choice BFF pattern hai: browser sirf Next.js server se baat karta hai, gateway aur AI service ke token server par hi rehte hain. Demo public hai, isliye samples cache se aate hain, uploads par IP rate limit, Turnstile, alag budget aur 24 ghante ka expiry hai, aur kuch bhi user tables me nahi likha jata. Admin me patient data by default chhupa hai; dekhne ke liye reason dena padta hai aur audit log pehle likha jata hai."

## Possible interview questions

1. **Demo pe koi asli report upload kar de to?** — Pehle notice + checkbox. Phir file sirf processing ke liye: EXIF strip, S3 `demo/` me, processing ke turant baad delete, 24 ghante lifecycle backstop, kisi user se link nahi, DB me nahi, logs me content nahi. Ye "sambhaal" hai, "rok" nahi: isiliye privacy page me bhi likha hai ki real documents mat daalo.
2. **Admin ko kya dikhta hai aur kyun?** — Stats, aur review queue me sirf metadata (id, kind, confidence, kitne items unclear). Content dekhne ke liye reason + audit. Phone number kabhi nahi, sirf user uuid.
3. **Server Components kyun?** — Landing/legal pages me zyada JS nahi chahiye (performance, SEO). Client components sirf wahan jahan state hai: playground, dialogs, charts.
4. **Bill na bhage iske liye demo me kya kiya?** — Samples cache se (zero cost), uploads par IP limit + Turnstile + alag daily budget; budget khatam to uploads band, samples chalte rahte hain. Aur AI service par `MAX_COST_PER_REQUEST_USD` pehle se hai.
5. **JWT dobara gateway par kyun check?** — Defence in depth: agar Next.js app compromise ho ya galat route ban jaye, gateway phir bhi bina valid signature/allowlist ke kuch nahi deta. Token 5 minute ka hai.
6. **Trace PHI ke bina kaise?** — `debug_trace` me sirf node naam, latency, model, tokens, cost, prompt version hota hai (M9). Koi text ya extraction value nahi.
