# M10 — Dose reminders + caregiver alerts (F4, F5)

## Is module me kya banaya
Prescription padhne ke baad user **[Reminder set karo]** dabata hai, bot saved medicines se summary dikhata hai (name, time, kitne din), user confirm karta hai (ya "subah 7, raat 10" likhkar time badalta hai). Phir har dose time par ek WhatsApp reminder aata hai with **[Le li] [Baad me] [Skip]**. Jawab na aaye to dose `missed` hota hai, aur lagataar 2 baar miss hone par **verified** family member (caregiver) ko ek chhota alert jaata hai. Sab gateway me hai (NestJS + BullMQ + Postgres), AI service me koi change nahi.

## Kyun zaroori tha
Bujurg patients dose bhool jaate hain, aur family ko pata nahi chalta. Reminder se adherence badhta hai, caregiver alert se family loop me aati hai. Dono me privacy ka risk hai (health info kisi dusre ko jaana), isliye caregiver ki **dono taraf se consent** aur alert me **minimum information** rakhi.

## Kaise kaam karta hai
```
rx:reminders:<doc> ──► ReminderFlowService.start ──► summary + [Haan set karo][Time badlo][Cancel]
                                                     (sirf saved medications se; SOS / unclear ko reason ke saath skip)
[Time badlo] ──► Redis "pending input" (10 min) ──► user ka text (encrypted) ──► parseCustomTimes ──► summary phir se
[Haan set karo] ──► reminder_schedules (1 per medication) ──► planner.planUser (turant)

                 every 15 min: reminder-planner (repeatable job)
                 schedules ──► slots (luxon, Asia/Kolkata) ──► reminders rows + delayed job  rem_<user>_<epoch>
                                                              (agle 36 ghante hi, baaki baad me)

slot time ──► ReminderDispatchService.sendSlot
              DB re-check ──► ek hi message (saari medicines) ──► outbound queue
              24h window ke andar: buttons message, bahar: template dose_reminder
              rows = sent, missed-check job (+60 min) queue me

user: [Le li] ──► taken (+ misses = 0)      [Baad me] ──► snoozed, +30 min par dobara (max 2, quiet hours me nahi)
      [Skip]  ──► skipped (missed nahi)     jawab nahi ──► missed-checker: sent -> missed, users.consecutive_misses + 1
                                            misses >= 2 ──► alert job ──► CaregiversService.alertMissedDose
```
Caregiver: `CAREGIVER +91…` → (webhook number ko **encrypted Redis** me rakhta hai) → "aapko ye kya bulate hain?" → label → `caregiver_invite` template → caregiver **YES** bhejta hai (number se pehchana jaata hai, onboarding se pehle) → `verified` → dono ko confirmation.

## Important technical decisions
| Decision | Reason / trade-off |
|---|---|
| **Rolling-window planner** (har 15 min, 36 ghante aage), saare jobs upfront nahi | Course 30 din ka ho to 60+ jobs upfront banana, edit/pause par sab hatana mushkil. Window me sirf agle 36 ghante badalte hain. Redis wipe ho jaye to agla planner run sab wapas bana deta hai |
| **Deterministic job ids** `rem_<user>_<epoch>`, `miss_…`, `snz_…_n`, `alr_…` | Planner kitni baar bhi chale, duplicate job nahi. Outbound job id `rem_<user>_<epoch>_<n>` se double send bhi nahi |
| **DB source of truth**, job payload nahi | Worker har baar user, schedule, rows dobara padhta hai. STOP / pause / delete ke baad bhi koi purana job kuch nahi bhejta |
| **Enqueue pehle, `sent` baad me** | Beech me crash ho to retry wahi outbound job id dobara daalta hai (no-op), reminder khoyega nahi |
| **UTC store, Asia/Kolkata compute** (luxon) | India me DST nahi, par code fixed offset assume nahi karta (test London zone se bhi) |
| **Ek slot = ek message**, `reminders` rows medicine-wise | 3 dawai ek time par = 1 notification (fatigue kam). Ack slot-level hai: `rem:taken:<epoch>` |
| **Button id me sirf epoch**, user sender se aata hai | Meta ka 128-char limit, aur koi dusre user ka slot ack nahi kar sakta |
| **Text queue me nahi** (M4 rule) → "pending input" Redis me encrypted | "subah 7, raat 10" ya caregiver label BullMQ job me nahi jaata; router Redis se ek baar padhta hai |
| **Missed vs skipped alag**; counter slot-wise (medicine-wise nahi) | Skip user ka sochha-samjha faisla hai, caregiver alert nahi. 3 dawai ek slot par miss = 1 miss |
| **Late ack** (6 ghante) `missed` ko `taken` banata hai | User ne dose li par button der se dabaya; adherence sahi rahe |
| **Caregiver ka double consent**, alert me sirf label + time | Template definition me medicine param hai hi nahi, test poora request serialise karke medicine naam dhoondhta hai |
| **Alert throttle** 6 ghante me 1, din me 3 (conditional UPDATE se claim) | Do worker ek saath alert na bhejein; caregiver ko spam nahi |
| Planner **cancelled rows ko revive** karta hai (sirf schedule ke current slots) | START REMINDERS / Resume ke baad aaj ke bache hue slots wapas aayein; "Time badlo" ke purane time wapas na aayein. Integration test me ye bug pakda gaya |
| Quiet hours me snooze nahi | Raat 22:30–06:30 me "30 min baad" reminder nahi; user ka explicitly diya time (22:00) phir bhi jaata hai |

## Production-ready points
- **Safety/privacy:** message content sirf DB se (no LLM, §2.5); caregiver ko no medicine name; phone hashed + encrypted (caregiver bhi); audit actions sirf ids/counts (`caregiver_invited`, `_verified`, `_declined`, `_removed`, `_alert_sent`, `reminders_scheduled`); queue jobs me phone/text/medicine name nahi.
- **Reliability:** idempotent ids, DB re-check, late slot (>10 min) kabhi nahi bhejta (silent `missed`, counter/alert nahi), invite 48 ghante me expire (sweep har 5 min), DELETE `reminders` queue ke jobs bhi hatata hai (`USER_JOB_QUEUES`) aur cascade se schedules/reminders/caregivers.
- **Tests:** 1000 unit tests (time parser table: Hindi/English/Hinglish, ack aliases, clock/quiet hours, templates, router, flows, webhook); `reminders.int-spec.ts` fake Asia/Kolkata clock me 5 din × 2 dose × 2 medicine: taken / snooze / skipped / missed / late / 3 caregiver alerts / completion; planner idempotency, no late send, pause/STOP/Galti hai, throttle, consent paths; `reminders-flow.int-spec.ts` webhook → router → workers → mocked Graph API tak.
- **Dev helper:** `REMINDER_TEST_OFFSET_MIN` (production me env validation refuse karta hai).

## Interview me kaise bolna hai
"Maine reminders ko ek rolling-window planner pe banaya. Har 15 minute me ek repeatable job agle 36 ghante ke slots Postgres me rows aur BullMQ delayed jobs ki shakl me bana deta hai, deterministic job ids ke saath, to planner kitni baar bhi chale duplicate nahi hota. Har worker DB ko source of truth maanta hai, job payload ko nahi, isliye STOP, pause ya DELETE ke baad koi stale job kuch nahi bhejta. Time UTC me store hota hai aur Asia/Kolkata me compute hota hai. Ek time par jitni dawaiyan hon, ek hi message jaata hai. Caregiver feature me dono taraf ki consent hai: caregiver ko YES bhejna padta hai, aur alert me sirf naam aur time jaata hai, koi dawai ya bimari nahi."

## Possible interview questions
1. **Server restart ho jaye to reminders ka kya?** Jobs Redis me hain (persistent). Redis bhi udd jaye to DB me rows hain aur planner har 15 min me jobs dobara banata hai (ids deterministic). Jo slot 10 min se zyada late nikla wo silent `missed` hota hai, late reminder nahi bhejte.
2. **1 lakh users ke reminders kaise scale karoge?** Jobs sirf agle 36 ghante ke hain; `(status, scheduled_at)` index; planner pages me chalta hai (200 schedules/page) aur kai workers par shard ho sakta hai (userId hash). Ek slot = ek outbound message, outbound queue rate-limited. Agla step: planner ko per-timezone shard karna aur slot jobs ko minute-bucket me batch karna.
3. **User time change kare to?** `rem:change` → naye times parse → `create` upsert karta hai, purane pending rows `cancelled` aur unke jobs queue se hatte hain, planner naye slots banata hai. Purane time ke rows revive nahi hote kyunki revive sirf schedule ke current slots ke liye hai.
4. **Caregiver ko kya-kya dikhta hai aur kyun?** Sirf user ka diya hua naam ("Papa") aur dose ka time. Dawai ka naam, dose, bimari kuch nahi (minimum necessary, DPDP). Template ke `bodyParams` me medicine hai hi nahi, aur test poora request search karta hai.
5. **Double tap ya message do baar aaye to?** Har ack conditional UPDATE hai (`status in (sent, snoozed)`), doosra tap `already` deta hai; snooze sirf `sent` par lagta hai, to double tap = 1 snooze. Outbound job id se same slot ka message do baar nahi jaata.
6. **24-hour window kaise handle hota hai?** Har reminder do roop me banta hai: buttons message aur `dose_reminder` template (same payloads). `OutboundService.deliver` send ke waqt window dekhta hai, window band ho to template jaata hai. Caregiver ke liye unka apna `last_inbound_at` hai.
